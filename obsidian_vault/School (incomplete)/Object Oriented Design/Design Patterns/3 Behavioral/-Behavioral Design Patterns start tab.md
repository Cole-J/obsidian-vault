The [[Design Pattern 3, Observer|Observer Pattern]] defines a way to implement a notification, or subscription style communication between objects.

The [[Design Pattern 4, Strategy|Strategy Pattern]] defines a way to have a classes logic not tied to one singular object, but rather a family of objects which are all interchangeable (even at runtime).

The [[Design Pattern 7, State|State Pattern]] defines a way to have classes change their methods behavior, with the changes being tied to some internal state. This is an extension of the Strategy Pattern, however each State is often tied to each other whereas each Strategy is kept separate.

The [[Design Pattern 8, Template Method|Template Method Pattern]] defines a way to create a skeleton, or template, of an algorithm split into multiple step methods. Then a subclass is able to define or override those step methods while keeping the overall algorithm the same.
